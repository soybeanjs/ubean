# i18n API

ubean's built-in i18n lives in the `@ubean/i18n` package — a zero-dependency module. It supports locale routing strategies, ICU-style pluralization, and `Intl.*` formatting via five format methods (`d`, `n`, `c`, `relativeTime`, `list`) plus `t`. The core APIs are re-exported from the `ubean` main entry; the Vue composable (`useI18n` from `ubean/runtime/vue`) is auto-imported in components.

## useI18n()

Access the i18n instance.

```typescript
import { useI18n } from 'ubean';

const i18n = useI18n();
```

### Properties

| Property         | Type     | Description                                |
| ---------------- | -------- | ------------------------------------------ |
| locale           | string   | Current locale code (e.g. `en`, `zh-CN`)   |
| fallbackLocale   | string   | Locale used when a key is missing (defaults to the configured default locale) |
| availableLocales | string[] | All registered locale codes               |

### Methods

| Method                                   | Description                                  |
| ---------------------------------------- | -------------------------------------------- |
| `t(key, params?)`                        | Translate a message (supports interpolation, plural, linked) |
| `setLocale(locale)`                      | Switch the current locale                    |
| `d(date, style?, options?)`              | Format a date with `Intl.DateTimeFormat`     |
| `n(number, style?, options?)`            | Format a number with `Intl.NumberFormat`     |
| `c(number, currency, options?)`          | Format a currency value                      |
| `relativeTime(value, unit, options?)`    | Format a relative time with `Intl.RelativeTimeFormat` |
| `list(items, style?, options?)`          | Format a list with `Intl.ListFormat`         |
| `onMissingKey(callback)`                | Register a missing-key handler               |
| `onLocaleChange(callback)`               | Register a locale change listener            |
| `addLocale(code, messages, options?)`    | Register a new locale at runtime             |
| `mergeLocale(code, messages)`            | Merge messages into an existing locale       |

## Standalone helpers

For use outside Vue components (e.g. inside API handlers or cron jobs), ubean re-exports the format functions as standalone helpers that operate on the current locale:

```typescript
import {
  t,
  formatDate,
  formatNumber,
  formatCurrency,
  formatRelativeTime,
  formatList,
  addLocale,
  mergeLocale,
  clearLocales
} from 'ubean';

const msg = t('welcome', { name: 'John' });
const formatted = formatDate(new Date(), 'short');
```

| Helper                       | Equivalent to               |
| ---------------------------- | --------------------------- |
| `t(key, params?)`            | `useI18n().t(...)`          |
| `formatDate(date, style?, options?)` | `useI18n().d(...)`   |
| `formatNumber(value, style?, options?)` | `useI18n().n(...)` |
| `formatCurrency(value, currency, options?)` | `useI18n().c(...)` |
| `formatRelativeTime(value, unit, options?)` | `useI18n().relativeTime(...)` |
| `formatList(items, style?, options?)` | `useI18n().list(...)` |
| `addLocale(code, messages, options?)` | `useI18n().addLocale(...)` |
| `mergeLocale(code, messages)`        | `useI18n().mergeLocale(...)` |
| `clearLocales()`                     | Clear all registered locales |

## Translations

### Basic translation

```typescript
const { t } = useI18n();

t('hello');                              // "Hello"
t('welcome', { name: 'John' });          // "Welcome, John!"
```

### Nested keys

```json
{
  "user": {
    "name": "User Name",
    "email": "Email Address"
  }
}
```

```typescript
t('user.name');   // "User Name"
t('user.email');  // "Email Address"
```

### Pluralization

```json
{
  "items": "no items | one item | {count} items"
}
```

```typescript
t('items', { count: 0 });  // "no items"
t('items', { count: 1 });  // "one item"
t('items', { count: 5 });  // "5 items"
```

### Linked messages

```json
{
  "app": { "name": "ubean" },
  "welcome": "Welcome to @:app.name!"
}
```

```typescript
t('welcome');  // "Welcome to ubean!"
```

### Missing keys

```typescript
const { t, onMissingKey } = useI18n();

onMissingKey((locale, key) => {
  console.warn(`Missing key "${key}" for locale "${locale}"`);
});

t('missing.key');  // returns "missing.key" and triggers the callback
```

## Date formatting — `d()` / `formatDate()`

```typescript
const { d } = useI18n();

d(new Date());                       // default style
d(new Date(), 'short');              // "1/15/26"
d(new Date(), 'long');              // "January 15, 2026"
d(new Date(), { dateStyle: 'full', timeStyle: 'short' }); // Intl options
```

## Number formatting — `n()` / `formatNumber()`

```typescript
const { n } = useI18n();

n(1234567.89);                       // "1,234,567.89"
n(0.42, 'percent');                  // "42%"
n(1234.56, { style: 'currency', currency: 'USD' });
```

## Currency formatting — `c()` / `formatCurrency()`

```typescript
const { c } = useI18n();

c(99.99, 'USD');                     // "$99.99"
c(1999, 'EUR');                      // "€1,999.00"
c(1500, 'JPY', { maximumFractionDigits: 0 });
```

## Relative time — `relativeTime()` / `formatRelativeTime()`

```typescript
const { relativeTime } = useI18n();

relativeTime(-1, 'day');             // "yesterday"
relativeTime(2, 'hour');             // "in 2 hours"
relativeTime(10, 'minute', { numeric: 'auto' });
```

## List formatting — `list()` / `formatList()`

```typescript
const { list } = useI18n();

list(['apple', 'banana', 'cherry']);                   // "apple, banana, and cherry"
list(['apple', 'banana'], 'disjunction');              // "apple or banana"
list(['apple', 'banana'], 'unit', { style: 'narrow' });
```

## Registering locales

Locales are auto-loaded from `src/locales/<code>.json` (or `.ts`) based on the `i18n.locales` config. To register additional locales at runtime (e.g. from a fetched bundle), use `addLocale`/`mergeLocale`:

```typescript
import { addLocale, mergeLocale } from 'ubean';

addLocale('fr', {
  hello: 'Bonjour',
  welcome: 'Bienvenue, {name} !'
}, { name: 'Français', dir: 'ltr' });

// Merge additional keys into an existing locale
mergeLocale('en', { newFeature: 'New feature' });
```

`clearLocales()` removes every registered locale — useful in tests.

## Locale detection

Locale is resolved in this order on every request:

1. URL path (when using `prefix` / `prefix_except_default` / `prefix_and_default` strategies)
2. `ubean_locale` cookie
3. `Accept-Language` header
4. `defaultLocale` from config

On a mismatch (e.g. cookie says `zh-CN` but URL is `/en/...`), ubean issues a `302` redirect to the correct localized URL and sets `Content-Language` on the response.

The current locale is hydrated on the client via a `<script id="__UBEAN_LOCALE__" type="application/json">` payload injected during SSR.

## Localized `<Link>`

When using a prefix-based strategy, `<Link to="/about">` automatically prefixes the current locale (`/zh-CN/about`) unless the `locale` prop overrides it:

```vue
<Link to="/about" locale="en">English About</Link>
<Link to="/about" :locale="false">Skip prefix</Link>
```

## `useLocalePath()` and `useSwitchLocalePath()`

For programmatic locale-aware navigation in `<script setup>`, ubean provides two composables from `ubean/runtime/vue` (also re-exported from the `ubean` main entry). Note they are **not** auto-imported — import them explicitly:

### `useLocalePath()`

Returns a function that resolves a route path to its localized form for the given (or current) locale:

```vue
<script setup lang="ts">
const localePath = useLocalePath();

// Resolves to "/zh-CN/about" when current locale is zh-CN
const aboutPath = localePath('/about');

// Explicit locale override
const enAbout = localePath('/about', 'en');
</script>
```

### `useSwitchLocalePath()`

Returns a function that builds a path to the current route in a different locale — useful for language switcher UI:

```vue
<script setup lang="ts">
const switchLocalePath = useSwitchLocalePath();
</script>

<template>
  <Link v-for="locale in locales" :key="locale.code" :to="switchLocalePath(locale.code)">
    {{ locale.name }}
  </Link>
</template>
```

```vue
<script setup lang="ts">
import { useLocalePath, useSwitchLocalePath } from 'ubean';

const localePath = useLocalePath();
const switchLocalePath = useSwitchLocalePath();
</script>
```

Both composables respect the configured `i18n.strategy` (`prefix`, `prefix_except_default`, `prefix_and_default`, `no_prefix`) and are SSR-safe.

## defineLocale()

Programmatically define locales from config (alternative to file-based loading):

```typescript
// ubean.config.ts
import { defineConfig } from 'ubean';

export default defineConfig({
  i18n: {
    defaultLocale: 'en',
    locales: ['en', 'zh-CN'],
    strategy: 'prefix_except_default'
  }
});
```

`i18n.locales` is a plain list of locale codes (`string[]`); per-locale metadata (display name, `dir`) is provided by the locale files themselves via `defineLocale()`. Calling `defineLocale()` is also how you register locales programmatically instead of via file-based loading.

## Best Practices

1. **Use `t()` for all user-facing strings** — never hardcode UI text.
2. **Keep message keys flat or shallow nested** — deep nesting hurts maintainability.
3. **Provide plural forms up front** — ICU `|` separator is required for correct pluralization.
4. **Avoid formatting in render hot paths** — `Intl` constructors are not free; cache formatted output when possible.
5. **Test missing-key behavior** — register `onMissingKey` in dev to surface gaps early.
