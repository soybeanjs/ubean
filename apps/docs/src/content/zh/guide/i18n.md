# 国际化

ubean 在 Vue 侧使用 **vue-i18n 11**（Composition API，必须 `legacy: false`），在 Hono handler 中使用 **`@intlify/core`**。语言路由是 **约束前缀**：由 `compileLocalePaths()` 编译一次，vue-router 与 Hono 共用同一张 path 表。

`useI18n` 直接从 `vue-i18n` 导入(自动导入需在 ubean.config.ts 设置 `autoImports: { vueI18n: true }`,默认关闭;否则请显式导入),`t` 从其返回的 composer 解构;`setLocale` 等 ubean 封装从 `ubean/client` 导入。

## 配置

全部写在 `ubean.config.ts`。检测中间件由 `createUbeanApp` **自动挂载**，不需要 `src/middleware/02.i18n.ts`。

```typescript
// ubean.config.ts
import { defineConfig } from 'ubean';

export default defineConfig({
  i18n: {
    defaultLocale: 'en',
    locales: [
      { code: 'en', language: 'en', name: 'English' },
      { code: 'zh', language: 'zh-CN', name: '简体中文' }
    ],
    strategy: 'prefix_except_default',
    baseUrl: 'https://example.com',
    detectBrowserLanguage: {
      cookieName: 'ubean_locale',
      redirectOn: 'root' // 默认
    },
    vueI18n: {
      fallbackLocale: 'en'
    }
  }
});
```

`locales: ['en', 'zh']` 会正规化为 `{ code }` 对象。`i18n: false`（或 locales 为空）关闭路由改写和中间件。

`language` 是 BCP 47，用于 `<html lang>` 和 `hreflang`。locale **code 是 URL 保留段**：若 `zh` 是语言 code，`pages/[id].vue` 不会把 `/zh` 当成 `id`。

### BCP-47 code + 短 URL 段

`code` 是 locale 的身份：cookie、文案目录、`<html lang>`、`hreflang`，以及传给组件库（如 `@vean/ui` 的 `SConfigProvider`）的值。它应当是完整的 BCP-47（`zh-CN`、`pt-BR`）。

如果同时希望 URL 短一些，加 `path`：

```typescript
i18n: {
  locales: [
    { code: 'en' },                                  // URL: /about
    { code: 'zh-CN', path: 'zh', name: '简体中文' },  // URL: /zh/about
    { code: 'pt-BR', path: 'pt' }                    // URL: /pt/about
  ],
  defaultLocale: 'en',
  strategy: 'prefix_except_default'
}
```

- URL 段用 `path`，其余全部用 `code`：`Set-Cookie: ubean_locale=zh-CN`、`Content-Language: zh-CN`、`<html lang="zh-CN">`、`hreflang="zh-CN"`。
- `/zh-CN/about` **不**可达（404）。`/zh/about` 是唯一入口。
- 两个 locale 映射到同一段会在配置加载期抛错 —— 否则后注册的那个会静默覆盖前者的路由。

拼页面链接时不要手写 `/${locale}/...`，用 `localizePath()` / `<Link to>`（`to` 会自动本地化）。

### 文案文件

约定目录 `src/locales/**/*.{json,json5,yaml,yml,ts,js}`。消息语法是 Intlify（不是 ICU）：`{name}`、`@:key`、`a | b | {n} c`。

```json
// src/locales/en.json
{
  "hello": "Hello",
  "welcome": "Welcome to ubean",
  "greeting": "Hello, {name}!",
  "items": "no items | one item | {count} items",
  "app": { "name": "ubean" },
  "linked": "Welcome to @:app.name!"
}
```

通过 `loadLocale(code)` 懒加载。SSR 只预载当前 locale + fallback；`__UBEAN_LOCALE__` 只序列化这两份。

## Vue 用法

```vue
<script setup lang="ts">
const { t, d, n, locale } = useI18n();

async function toZh() {
  await setLocale('zh'); // 加载文案 + 写 cookie + router.replace
}
</script>

<template>
  <h1>{{ t('hello') }}</h1>
  <p>{{ t('greeting', { name: 'World' }) }}</p>
  <button @click="toZh">中文</button>
  <p>当前：{{ locale }}</p>
</template>
```

**切换语言必须走框架 `setLocale`**，不要直接赋 `locale.value = 'zh'`。`setLocale` 会加载文案、写 cookie、再导航（`no_prefix` 跳过导航）。

语言切换按钮用 `getAvailableLocales()`：它返回 `{ code, path?, name?, dir, isDefault? }`，`code` 传给 `setLocale`，`name` 做标签。不要用 vue-i18n 的 `availableLocales`（水合后通常只有当前 + fallback），也不要自己拼 `/${code}/`（`path` 与 `code` 不同时会拼错）。

```vue
<script setup lang="ts">
const locales = getAvailableLocales();
</script>

<template>
  <button v-for="lc in locales" :key="lc.code" :lang="lc.code" @click="setLocale(lc.code)">
    {{ lc.name ?? lc.code }}
  </button>
</template>
```

它是普通函数（不是 `useXxx`）：读 `globalThis` 上的运行时单例，在路由守卫、事件处理器和 SSR 中都能调。

### 路径与 `<Link>`

```vue
<script setup lang="ts">
const localePath = useLocalePath();
const switchLocalePath = useSwitchLocalePath();
</script>

<template>
  <Link to="/about">About</Link>
  <!-- zh → /zh/about ；默认 en → /about -->
  <Link to="/about" locale="en">English About</Link>
</template>
```

`useLocalePath('/about', 'zh')` → `/zh/about`。`useSwitchLocalePath('zh')` 改写当前路由。

### 类型化 key

`ubean prepare` / `dev` / `build` 从默认 locale 的 JSON 生成 `.ubean/i18n.d.ts`，里面只有**数据**：`DefineLocaleMessage`（嵌套的 message 树）。

扁平化的 key 并集由框架**推导**，不写进生成文件：`LocaleMessageKey` 是 `DefineLocaleMessage` 的叶子路径并集（`'app.title' | 'common.hello' | …`），从 `ubean/client` 导入。

```typescript
import type { LocaleMessageKey } from 'ubean/client';

const key = 'common.hello' satisfies LocaleMessageKey; // ok
// @ts-expect-error 拼错的 key
const typo: LocaleMessageKey = 'common.hellp';
```

推导而非展开的价值：`DefineLocaleMessage` 是唯一事实源 —— 你在 `src/` 里手写的 `declare module` 增补也会进 union，生成文件也不会随 key 数量膨胀。

```typescript
declare module 'vue-i18n' {
  export interface DefineLocaleMessage {
    extra: { handWritten: string };
  }
}
// 'extra.handWritten' 自动出现在 LocaleMessageKey 里
```

注意 vue-i18n 自己的 `t()` **不校验** key：`Composer['t']` 的签名是 `<Key extends string>(key: Key | ResourceKeys | number)`，裸 `Key` 接受任意字符串，它内部的 `ResourceKeys`（`JsonPaths<DefineLocaleMessage>`）只提供补全提示。需要硬约束时，把 key 收在 `LocaleMessageKey` 上再传给 `t()`：

```typescript
function tk(key: LocaleMessageKey) {
  return t(key);
}
tk('common.hello');
tk('common.hellp'); // 类型错误
```

推导不要自己写：`@intlify/core-base` 导出了 `JsonPaths` 和 `RemoveIndexSignature`，vue-i18n 内部正是用这对组合推出 `ResourceKeys`，框架的 `LocaleMessageKey` 也直接用它们（见 `packages/client/src/i18n.ts`）。唯一不能省的是 `RemoveIndexSignature`：`DefineLocaleMessage` 继承自 `Record<string, …>`，带索引签名，直接套 `JsonPaths` 会退化成 `string`（于是任何拼写都能通过）。`@intlify/core-base` 与 `vue-i18n` 同版本钉在 catalog 里，脚手架默认 `shamefullyHoist: true`，项目里可直接解析到它。

## API / handler

handler 里从 `ubean/i18n` 导入的 `t()` / `d()` / `n()` 读请求 **AsyncLocalStorage**。没有请求作用域时抛错，禁止回落进程全局 locale。

```typescript
import { defineHandler } from 'ubean/server';
import { t, getRequestLocale } from 'ubean/i18n';

export const GET = defineHandler(c => {
  const locale = getRequestLocale(c);
  return c.json({ locale, hello: t('hello') });
});
```

`/api/`、`/_`、`/__` 仍进入 ALS（cookie / `Accept-Language`），但不改 URL。

Cloudflare Workers 需要 `nodejs_compat` 才能用 `AsyncLocalStorage`。ALS 不可用时 `t()` 抛错；请改读 `c.get('locale')`。

## 路由策略

Hono 与 vue-router 共用同一编译结果（`defaultLocale: 'en'`，locales `en, zh`，页面 `/about`）：

| strategy | vue-router | Hono |
| --- | --- | --- |
| `prefix_except_default`（默认） | `/:locale(zh)?/about` | `/about`、`/zh/about`（无 `/en/about`） |
| `prefix` | `/:locale(en\|zh)/about` | `/en/about`、`/zh/about` |
| `prefix_and_default` | `/:locale(en\|zh)?/about` | `/about`、`/en/about`、`/zh/about` |
| `no_prefix` | `/about` | `/about` |

检测顺序（有前缀的 strategy）：URL 前缀 → cookie → `Accept-Language` → `defaultLocale`。Cookie **会写入**。默认 `redirectOn: 'root'`：只有 `/` 会因 header 302；`/about` 不会。`prefix` 策略访问无前缀内容时无论 `redirectOn` 都会 302。

## SEO

SSR HTML 自动设置：

- `<html lang>` / `<html dir>`
- `link rel="alternate" hreflang`（含语言组 catchall 与 `x-default`）
- `canonical`（`prefix_and_default` 下默认语言指向 **无前缀** URL）
- `og:locale` / `og:locale:alternate`

客户端切换后可用 `useLocaleHead()` 更新 head。请配置 `i18n.baseUrl` 以生成绝对 hreflang。
