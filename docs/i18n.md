# 文档国际化流程

`apps/docs` 是**中英双语**站点，本文件说明译文如何生成、如何防漂移、以及哪些内容
**刻意不翻译**。翻译本身的用词规范见 [../apps/docs/TRANSLATION.md](../apps/docs/TRANSLATION.md)。

归属边界：本文件管**流水线机制 / 命令 / 环境变量 / CI**；[../apps/docs/TRANSLATION.md](../apps/docs/TRANSLATION.md) 管**逐文件译者规范**（frontmatter、链接、术语）；[../apps/docs/AGENTS.md](../apps/docs/AGENTS.md) 管**渲染期语义**。

## 覆盖范围

| 文档面 | 语言 | 门禁 |
| --- | --- | --- |
| `apps/docs/src/content/{en,zh}/**` | 双语 | ✅ 缺译文 / 漂移 / 结构不符都阻断 |
| `apps/docs/src/locales/{en,zh}.json` | 双语 | ✅ 键集必须一致 |
| 根 `README.md` + `README.zh_CN.md` | 双语 | ⚠️ 人工保证（见下） |

### 刻意不翻译

这份清单是流程的一部分，不是遗漏 —— 没有它，每次都要重新论证一遍：

| 面 | 原因 |
| --- | --- |
| `docs/**`（ADR / glossary / roadmap） | 维护者向工程文档，[README.md](README.md) 自述边界；用户向内容归站点 |
| `skills/**` | 喂给 AI agent 的提示词，语言一致比本地化重要 |
| `packages/*/package.json#description` | npm 元数据，英文是生态惯例 |
| `CHANGELOG.md` | `soy release` 从 commit 派生，重生成会覆盖译文 |
| `packages/*/README.md` | 目前仅 `vue` 有双语；其余包按需补，不进强制门禁 |

根 README 也不进门禁，理由记在 [ADR-0005](adr/0005-opt09-impl-opt11-timing-opt01-subitem.md)：
「避免三处同步维护又生新漂移点」。

## 引擎：Azure 优先，DeepL 回退

翻译引擎有两个实现，共用同一套分块 / 术语校正 / 结构校验卡口，差别只在请求层：

| 引擎 | 模块 | 选择条件 |
| --- | --- | --- |
| **Azure Translator**（默认） | `scripts/i18n/azure.mjs` | 存在 `AZURE_TRANSLATE_KEY` |
| DeepL（回退） | `scripts/i18n-translate.mjs` | 无 Azure 密钥，或显式 `--provider deepl` |

判据是「有没有 Azure 密钥」而不是「有没有 DeepL 密钥」—— 两个密钥可能同时存在
（本机 `~/.zshrc` 就同时导出），必须有确定优先级，否则「装了 Azure 却还在走 DeepL」
会成为静默的意外。`TRANSLATE_PROVIDER` / `--provider azure|deepl` 可显式覆盖；显式
值缺对应密钥时**报错而非静默回退** —— 静默回退会让「我以为在用 Azure」无从发现。

### 两个引擎的实测差异

**Azure 是 HTML 感知的**，这是它比 DeepL 更适合翻 markdown 正文的原因。`textType=html`
下真标签连同属性原样保留，所以驱动把行内代码 / 组件标签 / 链接目标换成占位符再送，
而不是像 DeepL 那样只能靠哨兵文本。裸送 markdown 的破坏形态（全部实测）：

| 片段 | Azure 裸送的结果 | 处置 |
| --- | --- | --- |
| `` `routeRules.prerender` `` | `'routeRules.prerender'`（反引号变单引号） | 占位符保护 |
| `[x](/guide/routing)` | `[x]（/guide/routing）`（全角括号，链接失效） | 保护 URL 部分 |
| `<Link to="/x">` | `<链接="/x">`（标签名被翻译） | 占位符保护 |
| `<SlotView name="dialog" />` | `<SlotView 名称="对话" />`（属性名被翻译） | 占位符保护 |
| `A & B` | 走实体处理 | `&` → `&amp;` |
| `if a < b` | 被当标签 | `<` → `&lt;` |

占位符形态 `XQZX<n>XQZX`。实测 8 个候选形态里只有这个全程不被改写：`§0§` 序号被
当数字重排、`\uE000` 整段被吞、`<ph id="0"/>` 属性引号变全角。

### 请求节奏：按字符预算调速，而非硬撞 429

Azure 计的是**源字符的滑动窗口**，不是请求次数。窗口的真实天花板远低于套餐表：在
`southeastasia` 上对真实负载实测 ——

| 观测量 | 实测结果 |
| --- | --- |
| 429 的性质 | 令牌桶拒绝，**不是**配额耗尽：突发后约 15s 自行恢复 |
| 突发额度 | 约 30 000 字符：10 000 × 4 的连发在第 4 个请求被拒 |
| 堵窗代价 | 约 70 000 字符会把窗口堵住约 30s |
| 可持续速率 | 约 555 字符/秒（500/s 连跑 60s 干净；1 000/s 与 2 000/s 都在约 35s 后失败） |
| 单请求传输上限 | >50 000 字符返回 `400077 The maximum request size has been exceeded.` |

所以驱动用**字符预算闸门**（`createCharacterBudgetGate`）主动调速：默认 1 500 000
字符/小时（可持续天花板的 75%）、单请求粒度 10 000 字符、容量取一个请求的量。闸门
记的是「本进程还欠窗口多少字符」，而不是把请求按固定间隔排开 —— 后者在某一批比
上一批更大时照样会超。

**闸门必须在一次运行里只建一次。** 按批新建等于每批都拿到一份满额预算，立刻冲进
429（上游 `sui translate` 第一次加闸门时正是这个 bug）；本项目用单测锁住这一条。
预算在**发请求之前**扣减，所以被拒的尝试也照样记账，它的重试要像其他批次一样排队。

429/5xx 的退避重试降为**兜底**：优先听 `Retry-After`（秒数或 HTTP 日期两种形态），
没有它才用自己的退避；原本「退避到 16s」的做法实测仍然会持续撞在同一个关闭的窗口上。
换套餐时用 `AZURE_CHARACTERS_PER_HOUR`（或 `AZURE_CHARACTERS_PER_MINUTE`，×60）与
`AZURE_CHARACTERS_PER_REQUEST` 覆盖。

切批粒度也是调速的一部分：默认按 10 000 字符（被调度的请求大小）切，而不是按
50 000 的传输上限 —— 粒度越大，一次抽走的容量越多，等待越突兀。

DeepL 那边不受影响：它是按请求行数（`TRANSLATE_BATCH_SIZE`，默认 24），且引擎自己在
一次 `translateBatch` 调用内完成全部切批；Azure 的切批与调速全在驱动里，调用方
不再切一层（再切只会把同一份预算拆成更多次请求）。

Azure 的 `category` 参数只接受内置分类值（传自定义值返回 `400002 The category
parameter is invalid.`），自定义术语表要走 Custom Translator（需单独训练部署）。所以
**Azure 路径的术语一致性完全靠本地替换**，DeepL 路径用原生 Glossary。

## 日常流程

### 只改了英文（最常见）

```bash
pnpm i18n:check                 # 看哪些篇漂移了
pnpm i18n:translate <slug>      # 增量翻译：只重译变了的节
pnpm i18n:check                 # 确认放行
```

`<slug>` 是相对 `src/content/en/` 的路径（`guide/islands`，`.md` 可省）。不传参数
则处理全部待译项 —— 注意那会消耗 DeepL 配额。

### 手工润色了译文

人工改过译文后，哈希基线需要更新：

```bash
pnpm i18n:stamp --force  # 重新盖章（--force 才更新已有标记）
pnpm i18n:check
```

**盖章是全站操作：没有 `--force` 之外的开关，也没有逐文件参数。** 脚本只读
`--force` / `--dry-run`，位置参数会被**静默忽略** —— 想靠附加路径参数「只重盖某一篇」
不会生效，结果反而是重写**每一篇** zh 的 `translatedFrom` / `sections` 为当前 en 哈希，
把「全站哪里漂移了」这个信号一次抹平。

### 新增一篇文档

在 `en/` 下写完后，让 zh 侧存在同名文件即可（可先用 `status: translated-stub`
占位，页面会显示英文正文 + 提示条），然后翻译。两者缺一都会被门禁拦下。

## 三个机制

### 1. 漂移判定：源哈希 + 分节指纹

译文 frontmatter 里有两个由脚本维护的字段：

```yaml
translatedFrom: 8d8e773906ba        # en 正文的 sha256 前 12 位
sections: ["3c354534", "e2b0..."]   # 逐节指纹（第 0 项是 title+description）
```

- **`translatedFrom`** 判「整篇是否过期」。哈希只覆盖**正文**：译文自己的
  frontmatter 必然不同（title 已译、多个 `translatedFrom`），算进去会让每篇永远漂移。
  归一化掉行尾空白与 CRLF，避免 Windows checkout 把全站标记为 stale。
- **`sections`** 判「**哪几节**过期」，让增量翻译成为可能。

两个字段都存在内容文件里而非旁挂状态文件 —— 它们随文件走，不可能与内容失同步。
两者的定义（归一化、指纹切分）以 `scripts/i18n/lib.mjs`（`sourceHash` / `sectionHashes`）
为真理源，本文件只描述用途。

### 2. 增量翻译：只重译变了的节

**整篇重译会把质量降级。** 实测在 `guide/introduction.md` 上，DeepL 把原本的
「文件式路由」（术语表用词）改成「基于文件的路由」，把「可移植服务端运行时」改成
**语义错误**的「可移植服务端 / 客户端运行时」。站点译文质量高于机器翻译时，全篇
重译是净损失。

所以翻译器按 `sections` 指纹逐节比对，只把不一致的节送去翻译，其余原样保留：

```
✓ guide/introduction.md（1 节重译，7 节保留）
```

### 3. 结构校验卡口：拒绝写入破坏结构的译文

落盘前比对结构指纹，不符就**拒绝写入并保留原译文**。校验项：标题层级序列、代码块
语言标注、站内链接条数、表格行数、行内代码数量（容忍量是 `max(5, count × 0.1)`：行内
代码数的差值 `drift > max(5, count × 0.1)` 才算破坏，绝对值 5 项是下限，避免小节被
百分比放大成误报）。

这不是多余的第二道保险 —— 它在实测中真的拦下过故障：DeepL 把同一批里的
`</Link>` 输出成 `</LINK>`，Vue 组件名大小写敏感，页面会渲染成未知元素且**构建不
报错**。现在这类问题被 `normalizeComponentTags()` 自动修好，其余结构破坏则被卡口拦下。

## 命令

```bash
pnpm i18n:check [--json|--summary|--max-drift N]
pnpm i18n:stamp [--force|--dry-run]
pnpm i18n:translate [--dry-run|--messages|--force|--no-glossary] [--provider azure|deepl] [slug]
```

环境变量：

| 变量 | 说明 |
| --- | --- |
| `TRANSLATE_PROVIDER` | 引擎选择：`azure`（默认，需有 Azure 密钥）/ `deepl`。`--provider` 优先 |
| `AZURE_TRANSLATE_KEY` | Azure Translator 密钥（**默认引擎**） |
| `AZURE_TRANSLATE_REGION` | Azure 资源区域，如 `southeastasia` |
| `AZURE_TEXT_TRANSLATE_URL` | Azure 端点，默认 `https://api.cognitive.microsofttranslator.com/` |
| `AZURE_CHARACTERS_PER_HOUR` | 字符预算，默认 `1500000`。换套餐时按实测窗口调整 |
| `AZURE_CHARACTERS_PER_MINUTE` | 同上，以分钟表达（×60），仅在没有 `PER_HOUR` 时生效 |
| `AZURE_CHARACTERS_PER_REQUEST` | 单请求字符粒度，默认 `10000`（硬上限 50000） |
| `DEEPL_API_KEY` | DeepL 密钥（`TRANSLATE_API_KEY` 作为别名）。以 `:fx` 结尾的免费版密钥自动走 `api-free` 端点 |
| `TRANSLATE_BASE_URL` | 覆盖 DeepL 端点 |
| `TRANSLATE_SOURCE_LANG` / `TRANSLATE_TARGET_LANG` | 默认 `EN` / `ZH`（Azure 侧自动映射为 `en` / `zh-Hans`） |
| `TRANSLATE_BATCH_SIZE` | **DeepL 专用**：每次请求的行数，默认 24（Azure 的切批与调速在驱动内，见上） |
| `TRANSLATE_GLOSSARY_NAME` | **DeepL 专用**：术语表名，默认 `ubean-docs` |

`--max-drift N` 容忍 N 篇漂移，用于渐进收敛期；缺译文与结构问题不受容忍。

## DeepL 的三个坑

实测失败与应对（不能直接翻 markdown、控制字符哨兵被转成 `elil`、XML 标签注入换行切碎
表格、必须开 Glossary、免费版只允许 1 个术语表且配额按字符计费）的**规范记录在脚本头
注释**：分块边界见 `scripts/i18n/chunk.mjs`，术语表译法与免费版限制见
`scripts/i18n-translate.mjs`。本文件不复制它们的措辞，只从流水线层面说：翻译单元是
**行**，结构行原样保留再按原行号回填。

## CI

`.github/workflows/ci.yml` 的 **Check docs i18n** 步骤跑 `node scripts/i18n-check.mjs`。
它只读文件、不调 DeepL，所以无需密钥、不消耗配额。缺译文 / 漂移 / 结构不符都会让
构建失败 —— 译文必须与内容更新同一个 PR 落地。

漂移此前是静默的（门禁上线前 en 有 43 次提交、zh 只有 38 次），这一步就是为了让它在
CI 暴露，而不是等读者发现页面还是英文。
