# 文档国际化流程

`apps/docs` 是**中英双语**站点，本文件说明译文如何生成、如何防漂移、以及哪些内容
**刻意不翻译**。翻译本身的用词规范见 [apps/docs/TRANSLATION.md](apps/docs/TRANSLATION.md)。

## 覆盖范围

| 文档面 | 语言 | 门禁 |
| --- | --- | --- |
| `apps/docs/src/content/{en,zh}/**` | 双语 | ✅ 缺译文 / 漂移 / 结构不符都阻断 |
| `apps/docs/src/locales/{en,zh}.json` | 双语 | ✅ 键集必须一致 |
| 根 `README.md` + `README.zh_CN.md` | 双语 | ⚠️ 人工保证（见下） |

### 刻意不翻译

这份清单是流程的一部分，不是遗漏 —— 没有它，每次都要重新论证一遍：

| 面 | 原因 |
| --- | --- |
| `docs/**`（ADR / glossary / roadmap） | 维护者向工程文档，[docs/README.md](docs/README.md) 自述边界；用户向内容归站点 |
| `skills/**` | 喂给 AI agent 的提示词，语言一致比本地化重要 |
| `packages/*/package.json#description` | npm 元数据，英文是生态惯例 |
| `CHANGELOG.md` | `soy release` 从 commit 派生，重生成会覆盖译文 |
| `packages/*/README.md` | 目前仅 `vue` 有双语；其余包按需补，不进强制门禁 |

根 README 也不进门禁，理由记在 [ADR-0005](docs/adr/0005-opt09-impl-opt11-timing-opt01-subitem.md)：
「避免三处同步维护又生新漂移点」。

## 日常流程

### 只改了英文（最常见）

```bash
pnpm i18n:check                 # 看哪些篇漂移了
pnpm i18n:translate <slug>      # 增量翻译：只重译变了的节
pnpm i18n:check                 # 确认放行
```

`<slug>` 是相对 `src/content/en/` 的路径（`guide/islands`，`.md` 可省）。不传参数
则处理全部待译项 —— 注意那会消耗 DeepL 配额。

### 手工润色了译文

人工改过译文后，哈希基线需要更新：

```bash
pnpm i18n:stamp --force <slug>  # 重新盖章（--force 才更新已有标记）
pnpm i18n:check
```

### 新增一篇文档

在 `en/` 下写完后，让 zh 侧存在同名文件即可（可先用 `status: translated-stub`
占位，页面会显示英文正文 + 提示条），然后翻译。两者缺一都会被门禁拦下。

## 三个机制

### 1. 漂移判定：源哈希 + 分节指纹

译文 frontmatter 里有两个由脚本维护的字段：

```yaml
translatedFrom: 8d8e773906ba        # en 正文的 sha256 前 12 位
sections: ["3c354534", "e2b0..."]   # 逐节指纹（第 0 项是 title+description）
```

- **`translatedFrom`** 判「整篇是否过期」。哈希只覆盖**正文**：译文自己的
  frontmatter 必然不同（title 已译、多个 `translatedFrom`），算进去会让每篇永远漂移。
  归一化掉行尾空白与 CRLF，避免 Windows checkout 把全站标记为 stale。
- **`sections`** 判「**哪几节**过期」，让增量翻译成为可能。

两个字段都存在内容文件里而非旁挂状态文件 —— 它们随文件走，不可能与内容失同步。

### 2. 增量翻译：只重译变了的节

**整篇重译会把质量降级。** 实测在 `guide/introduction.md` 上，DeepL 把原本的
「文件式路由」（术语表用词）改成「基于文件的路由」，把「可移植服务端运行时」改成
**语义错误**的「可移植服务端 / 客户端运行时」。站点译文质量高于机器翻译时，全篇
重译是净损失。

所以翻译器按 `sections` 指纹逐节比对，只把不一致的节送去翻译，其余原样保留：

```
✓ guide/introduction.md（1 节重译，7 节保留）
```

### 3. 结构校验卡口：拒绝写入破坏结构的译文

落盘前比对结构指纹，不符就**拒绝写入并保留原译文**。校验项：标题层级序列、代码块
语言标注、站内链接条数、表格行数、行内代码数量（容忍 10% 波动）。

这不是多余的第二道保险 —— 它在实测中真的拦下过故障：DeepL 把同一批里的
`</Link>` 输出成 `</LINK>`，Vue 组件名大小写敏感，页面会渲染成未知元素且**构建不
报错**。现在这类问题被 `normalizeComponentTags()` 自动修好，其余结构破坏则被卡口拦下。

## 命令

```bash
pnpm i18n:check [--json|--summary|--max-drift N]
pnpm i18n:stamp [--force|--dry-run] [slug]
pnpm i18n:translate [--dry-run|--messages|--force|--no-glossary] [slug]
```

环境变量：

| 变量 | 说明 |
| --- | --- |
| `DEEPL_API_KEY` | 必填（`TRANSLATE_API_KEY` 作为别名）。以 `:fx` 结尾的免费版密钥自动走 `api-free` 端点 |
| `TRANSLATE_BASE_URL` | 覆盖端点 |
| `TRANSLATE_SOURCE_LANG` / `TRANSLATE_TARGET_LANG` | 默认 `EN` / `ZH` |
| `TRANSLATE_BATCH_SIZE` | 每次请求的行数，默认 24 |
| `TRANSLATE_GLOSSARY_NAME` | DeepL 术语表名，默认 `ubean-docs` |

`--max-drift N` 容忍 N 篇漂移，用于渐进收敛期；缺译文与结构问题不受容忍。

## DeepL 的三个坑（实测）

1. **不能直接翻 markdown。** 整篇直送会让 `title:` 变 `标题：`（frontmatter 解析崩）、
   `</Link>` 被吞、`'virtual'` 变 `&#x27;virtual&#x27;`。占位符掩码（`\u0001`）会被转成
   `elil`；XML 标签（`<x id="n"/>`）会被注入换行把表格切碎。所以必须**分块**——
   只送可翻译的正文行，结构行原样保留再按原行号回填。详见 `scripts/i18n/chunk.mjs`。
   参考站 `soybean-ui` 的 DeepL 只处理扁平 JSON、从不碰它的中文正文，原因就在这。

2. **必须开术语表。** 不开时 `islands architecture` → 「岛式架构」、`partial hydration`
   → 「部分渲染」；开了 Glossary（条目来自 `TRANSLATION.md`）才对成「群岛架构」「部分水合」。

3. **免费版限制。** 只允许 1 个术语表，且 `PUT /glossaries/{id}/entries` 返回 401
   （需付费计划），所以更新条目只能**删除重建**。配额按字符计费，全站正文约 20 万字符。

## CI

`.github/workflows/ci.yml` 的 **Check docs i18n** 步骤跑 `node scripts/i18n-check.mjs`。
它只读文件、不调 DeepL，所以无需密钥、不消耗配额。缺译文 / 漂移 / 结构不符都会让
构建失败 —— 译文必须与内容更新同一个 PR 落地。

漂移此前是静默的（门禁上线前 en 有 43 次提交、zh 只有 38 次），这一步就是为了让它在
CI 暴露，而不是等读者发现页面还是英文。
